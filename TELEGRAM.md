# Уведомления о заказах в Telegram

Бэкенд отправляет два события: новый сохраненный заказ и подтвержденная оплата
ЮKassa. Сообщение содержит номер заказа, имя, телефон и адрес покупателя,
состав, итоговую сумму со скидками и доставкой и ссылку на админку.
Для авторизованного покупателя контакты берутся из профиля.

У нового заказа с онлайн-оплатой явно указано «Ожидает онлайн-оплаты».
После подтверждения платежа приходит отдельное сообщение «Заказ оплачен».
Создание заказа и подтверждение оплаты не ждут ответа Telegram.

## Подключение

1. Откройте https://t.me/BotFather в Telegram, отправьте `/newbot` и создайте
   отдельного бота для Horovatz. Сохраните выданный токен.
2. Для личных уведомлений откройте своего бота и нажмите «Запустить» / отправьте
   `/start`. Для команды добавьте бота в закрытую группу ресторана и отправьте
   в этой группе команду `/start@ИМЯ_БОТА`.
3. На Mac, из папки проекта, получите ID чата:

   ```bash
   python3 scripts/telegram_chat_id.py
   ```

   Скрипт попросит токен со скрытым вводом и покажет ID чатов из обновлений бота.
   Выберите именно чат ресторана; у групп ID обычно отрицательный. Токен
   скрипт не сохраняет. Этот способ использует `getUpdates` и рассчитан на
   нового отдельного бота без webhook и других обработчиков обновлений.
4. На VPS добавьте в `/opt/horovatz/.env`:

   ```dotenv
   TELEGRAM_BOT_TOKEN=ТОКЕН_ОТ_BOTFATHER
   TELEGRAM_CHAT_ID=ID_НУЖНОГО_ЧАТА
   ```

   Оба значения обязательны для включения уведомлений. Токен остается только
   на сервере; `.env` не отправляется в GitHub. Выбранный чат будет получать
   контакты покупателей и адреса доставки.
5. Обновите код и пересоберите бэкенд:

   ```bash
   cd /opt/horovatz
   git pull --ff-only origin main
   docker compose up -d --build backend
   docker compose logs --since=2m backend
   ```

   При включении в логах появится `Telegram order notifications enabled`.

## Проверка

Оформите тестовый заказ через сайт с понятным именем «Тест, не готовить».
Должно прийти уведомление с составом и итоговой суммой. Уведомление об оплате
проверяется только после подтвержденного платежа ЮKassa; для проверки без списания
денег используйте тестовый магазин ЮKassa. Затем отмените тестовый заказ в админке.

Наличие сообщения в чате проверяет фактическую доставку. Логи включения сами по
себе не подтверждают, что токен и ID чата корректны.

## Очередь и повторы

Очередь хранится в той же SQLite-базе, что и заказы, и переживает перезапуски.
Событие записывается в одной транзакции с заказом / оплатой. Повторный webhook
оплаты не создает новое событие. Ошибки Telegram не отменяют уже созданные заказы:
отправка повторяется с увеличением интервала, а при HTTP 429 учитывает `retry_after`.
После успешной отправки текст с контактами удаляется из записи очереди.

В редком случае Telegram мог принять сообщение, но ответ потерялся, либо сервер
перезапустился до фиксации результата: повторная доставка может создать дубль.
Номер заказа в сообщении позволяет его распознать. События, возникшие до включения
интеграции, задним числом не создаются.

Если сообщений нет, проверьте оба значения, запуск личного диалога / участие бота
в группе и его право писать сообщения. Затем смотрите:

```bash
docker compose logs --since=10m backend
```

В логах не выводятся токен и текст сообщения. HTTP 401 обычно указывает на токен,
400 — на ID чата или запрос, 403 — на блокировку бота или отсутствие прав.
После исправления `.env` выполните `docker compose up -d backend`.

Без обоих параметров интеграция отключена, сайт работает как прежде.

API: https://core.telegram.org/bots/api#sendmessage
