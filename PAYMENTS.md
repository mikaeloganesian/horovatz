# Обновление статуса оплаты

Статус оплаты обновляется только при входящем webhook ЮKassa.
Страница `/payment/return` читает сохраненный статус заказа из нашей базы;
ее запросы не обращаются в ЮKassa и не изменяют оплату.
При получении webhook сервер один раз проверяет платеж через API ЮKassa:
ID платежа, `metadata.order_id`, сумму и валюту RUB.
Оплата подтверждается только при `status=succeeded` и `paid=true`.
`waiting_for_capture` не считается завершенной оплатой.

Подтверждение обновляет заказ и ставит Telegram-уведомление в очередь в одной
транзакции. Повторные проверки и webhook не создают повторные события оплаты.

Страница продолжает проверку каждые 2 секунды, затем каждые 5 секунд, пока открыта.
При длительном ожидании есть кнопка «Проверить сейчас».
Если проверка webhook или запись в базу не удалась, обработчик возвращает 5xx:
ЮKassa повторяет доставку уведомления. Если webhook пришел раньше, чем платеж
привязался к заказу, обработчик отвечает 503, а не теряет событие с ответом 200.

В кабинете того же магазина ЮKassa, чьи ключи указаны на VPS, откройте
«Интеграция → HTTP-уведомления» и укажите:

- URL: `https://horovatz.ru/api/payments/yookassa/webhook`
- События: `payment.succeeded`, `payment.canceled`.

Обработчик перепроверяет платеж через API и не доверяет статусу из тела webhook.

Обновление VPS:

```bash
cd /opt/horovatz
git pull --ff-only origin main
docker compose up -d --build backend web
```

## Диагностика доставки

```bash
docker compose logs -f --tail=0 backend web
```

В access-логах должен появиться `POST /api/payments/yookassa/webhook`.
В логах бэкенда есть отдельные сообщения:

- `yookassa webhook received` — запрос получен, началась проверка подлинности;
- `yookassa webhook processed` — статус записан, можно отвечать 200;
- `requesting redelivery` — временная ошибка, ожидается повтор ЮKassa.

Если POST вообще отсутствует, проверяйте URL и выбранные события в нужном магазине,
DNS домена, доступность HTTPS и сетевые правила VPS. Если POST есть, его код ответа
и соседнее сообщение бэкенда указывают, на каком этапе остановилась обработка.
Открытие страницы возврата не заменяет повторную доставку webhook для старого платежа.

Правила настройки и повторной доставки: https://yookassa.ru/developers/using-api/webhooks
